GUÍA RÁPIDA DE INSTALACIÓN
==========================

Este fichero es una chuleta para terminal. README.md es la documentación
canónica y explica arquitectura, seguridad, YAML, Ollama, Cloudera y capacidad.

1. Crear y activar el entorno aislado:

   python3 -m venv .venv
   source .venv/bin/activate

2. Instalar exactamente las dependencias del proyecto:

   python -m pip install --upgrade pip
   python -m pip install -r requirements.txt

3. Crear `.env` a partir de `.env.example`. `OPENAI_API_KEY` sólo es necesaria
   si se usan modelos OpenAI. La entrada LiteLLM no requiere master key.

4. Revisar `config.yaml`. Nunca edites `runtime/active_config.yaml`: es una
   copia generada automáticamente.

5. Arrancar el panel:

   ./start.sh

   Si Cloudera ejecuta directamente "python app.py", el propio módulo crea un
   .venv privado, instala requirements.txt dentro y se relanza con ese Python
   antes de cargar FastAPI. Así no modifica ni entra en conflicto con MLflow y
   los paquetes del runtime de Cloudera. Un fallo cancela el arranque y muestra
   la causa en el log de sesión. La instalación elimina cualquier PIP_USER
   heredado, no utiliza --user ni --no-user, y usa Python -I para no heredar
   MLflow, PYTHONPATH ni constraints globales. En modo celda mantiene el engine
   como padre para que el visor de Cloudera conserve todos los mensajes. También
   ignora el pip.conf externo que pueda imponer "user = true" y muestra toda la
   salida de pip con las últimas 30 líneas incluidas en cualquier error.
   Si el runtime lo evalúa como celda y no existe __file__, usa como alternativa
   el directorio de trabajo actual del proyecto.

6. El proxy streaming `aiohttp` se instala desde requirements.txt. No requiere
   paquetes del sistema y se ejecuta como proceso separado del panel.
7. Abrir https://127.0.0.1:8090 y pulsar «Arrancar».

El proxy escucha en ${IA_GATEWAY_PORT:-8090}; dentro del contenedor reenvía `/v1/*`
directamente a LiteLLM en 127.0.0.1:${IA_GATEWAY_LITELLM_PORT:-14000} y las demás
rutas al panel en 127.0.0.1:${IA_GATEWAY_DASHBOARD_PORT:-18080}. Cloudera sólo
publica esa entrada. En local el proxy usa el certificado HTTPS autofirmado.

Las conexiones y tokens CDP se guardan en `runtime/cloudera.sqlite3`. SQLite
forma parte de Python y no requiere servidor, Docker ni instalación adicional.
El callback lee el token vigente antes de cada llamada, por lo que una renovación
se aplica sin reiniciar LiteLLM.
