            Cloud · token CDP renovable automáticamente
            
El JWT es temporal. IA Gateway puede regenerarlo antes de caducar utilizando un Access Key ID y Private Key.

            
            
            
            
            
          


          

            Endpoint directo de Workbench
            
Este modo conecta un deployment publicado como POST /model. El accessKey identifica el modelo y se guarda localmente como secreto; no es un CDP token ni la API key personal de Workbench.

            
            
            
            
            
            
            
            
Para listar todos los proyectos y deployments mediante /api/v2 se necesita una API key del propio Workbench. Un Access Key ID y Private Key de CDP no sustituyen esa API key.

          


          

            On-premise · autenticación de CAI Inference
            


            

              
              
Pega un CDP_TOKEN de UMS o, únicamente en combinaciones certificadas, una Knox API key. Estas credenciales no se pueden regenerar sin las credenciales IAM de la opción 2.

              
              
              
            


            

              
              
IA Gateway genera el primer token y vuelve a ejecutar generate-workload-auth-token antes de caducar, sin reiniciar LiteLLM. El comando set-authentication-policy sólo cambia la duración global; no crea ni refresca tokens. Cloudera exige una access key y private key de usuario o machine user; el usuario/contraseña general no sirve para firmar esta API IAM.

              
              
              
              
              
              
              
La conexión será vulnerable a suplantación. Úsalo sólo para diagnosticar y configura después la CA privada.

            

          


          

        

        
Ciclo de vida: IA Gateway detecta la caducidad de los JWT y programa la renovación antes de que entren en riesgo. Sólo muestra renovación automática cuando dispone de un mecanismo no interactivo compatible; las API keys opacas de Knox o Workbench deben rotarse antes de su fecha administrativa.

¿Aplicar los cambios de modelos ahora?
Añadir, editar o eliminar modelos requiere reiniciar LiteLLM y puede interrumpir llamadas durante unos segundos. Los cambios de credenciales Cloudera se aplican sin reinicio.

  
¿Limpiar este log de LiteLLM?
Se eliminarán las líneas de la jornada seleccionada. Los logs de peticiones de los modelos no se verán afectados.

  
¿Eliminar este modelo?
También se limpiarán sus fallbacks, estado y uso como guardrail. Los logs históricos se conservarán.

  
¿Eliminar esta conexión?
Se eliminarán también las credenciales de modelos asociadas. Los modelos ya incorporados a config.yaml no se borrarán.
